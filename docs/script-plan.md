# Rust script experience plan

Status: Phase 5 underway (WIT frozen, sandboxed host, gate number, Play wiring, Rust and C guests landed; wasmtime component host landed; Python gate measured, TypeScript and the rest next). Analysis of the current script system against Unity's coded scripts, with gaps and a phased improvement plan.

Goal: make Rust scripts a first-class alternative to blocks for game logic. A script author should get per-instance state, inspector-tunable params, typed APIs over any actor, sane timing primitives, and editor feedback (check, format, docs, debug) without installing a toolchain or leaving Blockloom. Scripts stay another way to drive an actor, not another engine: reads from the same `sense` snapshot, writes as the same `vm::Effect`s.

## Baseline before this plan

- One `.rs` file per actor, named by `Script { path }` (`blockloom-core/src/components.rs:354`) under `assets/scripts/`. `create_script` scaffolds from `script::starter` and attaches the component (`blockloom-app/src/commands.rs:3889`).
- Build is two `rustc` runs, no Cargo/network: the `blockloom` rlib assembled from `script/abi.rs` + `script/prelude.rs`, then the script as a `cdylib` (`blockloom-core/src/script/mod.rs:274`). `std` only, edition 2024, `-O2`. Cache key is ABI + toolchain + target + source length (`mod.rs:260`); host builds reuse Play's output dir, cross builds get a triple-named dir (`mod.rs:107`).
- Boundary is `script/abi.rs:12` (`ABI_VERSION = 40`). Three host calls in `HostApi` (`abi.rs:486`): `read_number`, `read_text`, `act`. New verbs are new constants so old libs keep loading until the version check rejects them (`blockloom-runtime/src/script.rs:110`).
- Runtime opens libs with `libloading`, checks the ABI, and calls `start` once per actor (late clones included), then `tick(dt)` + `event(kind, n0..n3)` each fixed step (`blockloom-runtime/src/world.rs:1081`, `simulation.rs:130`). `step_scripts` is skipped while paused (`world.rs:1087`). Effects join the VM's list; read-after-write returns the old value, same as blocks.
- Web builds compile each script to its own `.wasm` importing `blockloom::{read_number,read_text,act}` with a null `HostApi` (`abi.rs:567`); Android resolves the lib by file name beside the runtime (`script.rs:61`).
- Editor is `ScriptDialog.qml`: a plain `TextEdit` with regex highlight, gutter, on-demand `read/write/check_script` and `script_diagnostics` via `cargo check --tests` or `rustc --error-format=json`. `script/ide.rs:178` synthesizes a root `Cargo.toml` + `blockloom` crate under `.blockloom/ide` so rust-analyzer works in an external editor. `check`/`build_scripts` log raw `rustc` stderr to the run log; a failed script silently does not load and Play carries on (`commands.rs:2608`).

## Unity comparison

| Area | Unity (`MonoBehaviour`) | Blockloom baseline |
| --- | --- | --- |
| Lifecycle | `Awake/OnEnable/Start/Update/FixedUpdate/LateUpdate/OnDisable/OnDestroy`, coroutines (`yield WaitForSeconds`), `Invoke` | `start/tick/event` via `export!` (`prelude.rs:3130`). `tick` is fixed-step only, no frame/late split, no destroy/disable/stop hook, no wait primitive. |
| State | Per-instance fields, `[SerializeField]` Inspector UI, per-prefab overrides | `Actor { ctx, api }` holds no user state (`prelude.rs:128`). No fields, no Inspector rows. One file shared by N actors shares `static`s. Only persistence is `save_variable` with no script-side read/write of block variables. |
| Scope | Multiple components per object, `GetComponent`, `GameObject.Find`, act on any object | One script per actor; almost every `act_for` pins `actor = ctx.actor` (`script.rs:1001`). Scripts move/tint only themselves; cross-actor ops are limited to clone/delete/parent/sound-at plus single-axis `position_of`. |
| API shape | Typed (`transform.position`, `Rigidbody.velocity`, enums), compiler-checked | Stringly typed: key names, dial strings (`"direction"`, `"set radius"`), `"#RRGGBB"` colors, component/field/action names. Typos answer `MISSING`/zero at runtime. |
| Tooling | Roslyn shipped with the editor, IntelliSense, debugger, incremental compile on save | Requires the user's own `rustc`; no in-app completion/hover/signature, no formatter, no breakpoints/watches, diagnostics only on open/`Check`. Panics log `"panicked in {what}"` with no location (`prelude.rs:2868`). |
| Iteration | Compile on save, domain reload, hot state | Compile on Play/`Check`. No attach mid-run, no hot reload. ABI bumps invalidate every build until `.blockloom/build` rebuilds. |

## Background: Pumpkin-MC WASM plugins (research)

Pumpkin-MC moved plugins from native libs to WASM components for sandboxing, cross-platform shipping, crash isolation, marketplace validation, and multi-language support (issue #662; Extism tried and dropped as too heavy, wasmtime preferred).

- Unit is a `wasm32-wasip2` component, not a native lib. The interface is defined in WIT, not in a language API: `pumpkin-plugin-api` calls `wit_bindgen::generate!` with `world: "plugin"`, host exposes typed interfaces (`command`, `server`, `permission`, ...), guest exports `init-plugin`, `on_load`/`on_unload`, `handleCommand`/`handleEvent`, `get_metadata`.
- Each language has a thin guest binding over the same WIT world (`pumpkin-api-go`, `-py`, `-cs`, `-kt`, `-c`, `-d`, `-zig`, `-ts`, listed at `docs.pumpkinmc.org/plugin-dev/introduction`), each with its own componentize toolchain: Rust `cdylib` + build tool, Go via `TinyGo` (`tinygo build -target=wasi`; standard Go does not emit the right component), C# via .NET 10 `wasi-wasm` RID + `Componentize.DotNet` SDK, Kotlin via Gradle `wasmWasi`, C via `wasi-sdk clang -mexec-model=reactor`, TS/Python via bundler + componentize script.
- Host runs them in a WASM runtime with a permission + WASI-sandbox model: `PluginMetadata.permissions` gates `fs.read.data`/`fs.write.data`, network DNS, sys-info fields; storage is plain files via the language's normal `std::fs` under a per-plugin data folder from `Context.get_data_folder`. Lifecycle callbacks are re-entrant: docs warn not to hold a non-reentrant lock across a host call.
- Native-vs-WASM stays an explicit tradeoff in their thread: sandboxing and language reach vs native-only needs (sockets, codecs, GPU libs, AVX/OpenCL, HW video) and bigger debug/perf costs. Plan kept both paths open.

Blockloom already has half of this: portable plugin modules run WASM under `wasmi` with two imports (`blockloom-plugin-host/src/portable.rs:1`, `blockloom-plugin-api/src/wasm.rs`), and web scripts are already per-script `.wasm` modules (`mod.rs:145`). Desktop scripts (`rustc cdylib` + `libloading` + 3-function C ABI) are the outlier this phase would replace or parallel.

## Gaps

1. No per-instance state or inspector params. Forces `static`s (shared across actors using the same file), custom-component hacks, or side files.
2. Self-only writes and no variable bridge. Scripts cannot drive other actors' transforms/physics/appearance or read/write block variables and lists, so mixed block/script logic has no shared working memory.
3. Poor time model. No `wait`/timer/interval helpers, no tween-end or animation-end subscription from `tick`, no fixed-vs-frame split, no pause-aware UI tick, no stop/destroy cleanup.
4. Thin physics reads. Scripts can push/set velocity/add force/query/raycast but cannot read velocity, angular velocity, mass, or contact detail outside events; `position_of` is one axis at a time.
5. Editor feedback. Tokenizer highlighting only; no continuous check, format, clippy, API docs, generated project symbols (actor/component/field names), or debugger/profiler attribution.
6. Iteration and platform cost. Per-file `-O2` `cdylib` builds on Play; cross builds need target `std` plus a linker (Android NDK wrapper, wasm `rust-lld`); failures arrive as raw `rustc` stderr in the run log.

## Plan

### Phase 0: small correctness and debuggability wins

- [x] Log panic location and message from `guard`, keeping the catch-and-log contract so a script still cannot take the window down. Native guards capture the actual panic site through a hook, with `Location::caller` as a fallback; web's abort hook already reports the panic site. Tests cover exported callbacks, non-string payloads, nested guards, concurrent threads and continuing after a panic.
- [x] Invalidate script caches when the prelude changes, and fingerprint source contents so same-length edits cannot reuse stale builds.
- [x] Keep per-script build and load status in editor state. Show missing builds, compiler errors, ABI mismatches and loader errors in `ScriptDialog` and the Inspector card, alongside the run log. Saving clears the previous result; a successful check or load replaces failures.
- [x] Add `pose()` and `pose_of()` batch reads (position + rotation + scale in one call). Fixed 28-byte records use the existing buffer callback on native and web; self reads avoid allocations and cloning the actor snapshot. Document call costs and snapshot timing in the [script read guide](script-api.md). Script ABI became 41 then.
- [x] Add missing motion readback for blocks and scripts alike: velocity/angular velocity/mass reads plus a grounded flag without requiring a controller move. `ActorSense` carries `velocity`, `angular_velocity`, `mass` and `grounded`, sampled in `world::sample_actor_senses` from Rapier (`Velocity`, `ReadMassProperties`) and the contact tracker (a solid face below, 45 degrees). Blocks get `Velocity`, `AngularVelocity`, `Mass` and `IsGrounded` reporters; scripts get `READ_VELOCITY`, `READ_ANGULAR_VELOCITY`, `READ_MASS`, `READ_GROUNDED` with `velocity[_of]`, `angular_velocity[_of]`, `mass[_of]`, `grounded[_of]` methods (ABI 42). Multi-axis `position_of` is already covered by `pose()`/`pose_of()`. `is_grounded()` keeps its controller last-move meaning; `grounded()` is the contact one.

### Phase 1: state and scope (the Unity gap)

- [x] Host-owned per-actor script storage, keyed by actor id, cleared on run start. A `ScriptData` map in core (numbers + text, kind-strict, empty keys refused) backs `READ_DATA`/`TEXT_DATA` and immediate `ACT_SET_DATA`/`ACT_SET_DATA_TEXT`/`ACT_CLEAR_DATA` verbs (ABI 43, so the web path rides the same three imports). Prelude: `data`, `data_text`, `has_data` (presence probe), `set_data`, `set_data_text`, `clear_data`, `clear_all_data`. Writes land at once, so read-after-write sees them; each clone keeps its own keys; a run starts empty and nothing is saved. Documented in the [script read guide](script-api.md). Timers, cooldowns and multi-tick behavior no longer need `static`s.
- [x] `World`/`ActorRef` handle for cross-actor reads and writes (`me.world().actor("Ball").go_to(..)`), lowering to the existing `Effect`s with an explicit target id. Host resolves by id then case-insensitive name (empty, `me` and `myself` mean self); a miss is an `Effect::Error` for the runner. Covers transform (`go_to`, `change_position`, `move_forward`, `turn`, `set_rotation`, `set_scale`, `point_towards`), appearance (`say`, `set_visible`, `set_color`) and velocity (`push`, `set_velocity`, `add_force`/`add_torque`) as `ACT_*_OTHER` verbs (ABI 44, same three imports on web). Reads reuse the `*_of` snapshot helpers (`pose` covers rotation/scale), so deferred-effect semantics hold: read-after-write still reads old. Documented in the [script read guide](script-api.md).
- [x] Script access to block variables and lists (read + write + save), so a canvas counter and a script counter can be the same counter. `variable`/`variable_text`/`set_variable`/`set_variable_text`/`change_variable` and `list_len`/`list_number`/`list_text`/`list_add[_text]`/`list_insert[_text]`/`list_replace[_text]`/`list_delete`/`list_clear` ride `READ_VARIABLE`/`TEXT_VARIABLE`/`READ_LIST_LENGTH`/`READ_LIST_ITEM`/`TEXT_LIST_ITEM` and immediate `ACT_SET_VARIABLE[_TEXT]`/`ACT_LIST_*` verbs (ABI 45, same three imports on web). The host shares the run's `Variables`/`Lists` with scripts for the step, so writes land at once like the VM's and `save_variable` persists them unchanged. Documented in the [script read guide](script-api.md).
- [x] Shared script modules and several scripts per actor, with a defined call order. Any file under `assets/scripts/shared/` is library code pulled in with `mod` (usually `#[path]`), never built alone or attached; its edits invalidate every script build, and the IDE checks it as part of its includers. `Components` treats `Script` as repeatable by path (`scripts()`, `remove_script`, `move_script`), with `add_script`/`remove_script`/`move_script` commands plus a path-aware `set_actor_component` rename, and the inspector stacks cards with Up/Down for the run order. The runtime opens every script in component order and runs `start`, then `event`, then `tick` top to bottom, sharing one store. Documented in the [script read guide](script-api.md).

### Phase 2: timing and lifecycle

- [x] Split `tick` into fixed and frame variants (physics vs camera/UI motion), and add a UI tick that runs while paused so script-driven menus match block-driven ones. `tick` stays the fixed step; optional `frame` runs once per rendered frame while unpaused and `ui` once per rendered frame even while paused (ABI 46, same three imports on web). While paused the fixed step leaves events queued and the frame system hands them to `event` alongside `ui`, so nothing is heard twice. Documented in the [script read guide](script-api.md).
- [x] Timer helpers in the prelude (`after`, `every`, cooldowns) built on `dt` accumulation, plus `on_stop`/`on_destroy` and scene-end cleanup. Keyed `Actor::after`/`every`/`cooldown_ready`/`cooldown_trigger`/`cooldown_tick` keep per-actor countdowns in script storage (clones included); plain `Timer`/`Every`/`Cooldown` structs cover single-actor files. Optional `stop` runs on run end (speech, errors and saves land) and `destroy` when the actor is deleted or its script detached; `Event::SceneEnded` still covers scene-end cleanup. Documented in the [script read guide](script-api.md).
- [x] Tween/animation completion and `wait`-equivalent sequencing without blocking: pollable handles or events, not threads. `is_tweening()` polls glides and tweens, `Event::AnimationEnded`/`AnimationMarker` arrive in the fixed-step `event`, and waits are small state machines over `after`/`every` plus those two. Documented in the [script read guide](script-api.md).

### Phase 3: typed API and generated symbols

- [x] Typed dials over stringly calls (`WindDial`, `WaterDial`, `ForceMode`, color type), following the existing `Axis`/`CameraView` pattern. `script::typed` ships `ForceMode`, `WindDial`, `WaterDial`, `CloudDial`, `Precipitation`, `Easing` and `Color` (compiled into the `blockloom` crate like `timing`), with checked `Actor`/`ActorRef` methods beside the string ones (`add_force_mode`, `set_wind_dial`, `set_water_dial`, `set_clouds_dial`, `set_precipitation_kind`, `tween_*_eased`, `set_color_rgb`). Names match the core parsers, covered by a parse-back test; the strings keep building.
- [x] Project symbols for scripts (actor names/ids, custom component fields, input actions, plus shared variables/lists) as a checked module, so renames break compile instead of silently reading zero. `script::symbols` generates `blockloom::symbols` per project at build time (in the `blockloom` rlib and the IDE crate); renames change the stamp and rebuild every script. Empty when the project names nothing, so tests and fresh folders still compile; generated code is itself compiled by a test.
- [x] A blocks-to-scripts Rosetta page (`docs/script-rosetta.md`): each block with its `Actor::` equivalent (control flow as Rust, hats as `Event`s, reporters as readers, dials as typed enums, names as `symbols::`), and the `starter` template (`mod.rs:67`) as the canonical example pointing at it.

### Phase 4: editor experience

- [x] Background `cargo check` on `write_script` with continuous inline diagnostics, plus Save+Format (`rustfmt`) and an opt-in Clippy pass. Saving re-runs `script_diagnostics` on what's on screen, and two quiet seconds do too (a debounced `Timer` in `ScriptDialog.qml`); `format_script` runs `rustfmt --edition 2024` over the file and writes it back (`ide::format_source`), `clippy_script` runs `cargo clippy --message-format=json --tests` filtered to the script (`ide::clippy_for`). Both buttons disable with a one-line install note when `rustfmt`/`clippy` are missing (`ToolchainStatus` carries both versions).
- [x] In-app completion/hover from the existing `.blockloom/ide` project (or an LSP client), project-symbol completion, and one-click open in the user's editor with the current flow kept. `script::complete` scans `PRELUDE_SOURCE` (methods, consts, enum variants with doc lines) and parses the generated `symbols` source back into `symbols::...` paths; `script_completions`/`script_hover` serve them (shell/MCP included), `Ctrl+Space` lists them with docs in `ScriptDialog.qml`, and `open_script_ide` keeps the one-click external flow.
- [x] Script-aware run log: log levels, per-script timing rows in the profiler, and failure states that link back to the file/line. `LogLine` carries `level` (`info`/`error`) plus `path`/`line` (`LogLine::script_error` parses the first `path:line` span); build, check, load and runtime errors resolve the actor's script file (exactly-one-script lines link, ambiguous ones don't), `RunLog.qml` offers `Open script` onto that line via `InspectorPanel.openScript`, and `Engine.script_times` reports smoothed per-file ms as `script/…` profiler rows.
- [ ] Ship-a-toolchain decision (open question below) still stands: packaged installs can't assume `rustc`, and neither `rustfmt` nor `clippy`.

### Phase 5: multi-language scripts via WASM components (Pumpkin-style)

Do scripts second, not first: prove the WIT world in the plugin host, measure per-tick overhead against the `cdylib` path, then decide whether desktop scripts migrate or run side by side (native for trusted local use, WASM for sandbox/marketplace, same split Pumpkin kept open).

- [x] Freeze a script WIT world equivalent to the current `READ_*/TEXT_*/ACT_*` + `start/tick/event` surface. `blockloom-core/src/script/wit.rs` pins the frozen `blockloom:script@0.1.0` world (`WIT_VERSION` 1): typed homes for the hot paths (`lifecycle.pose`, `state.*`, `vars.*`, `lists.*`, `physics.*`, `plugins.*`, the `event` variant) with the long tail riding each interface under its verb's kebab-case, one table row per verb. A coverage test parses `abi.rs` and refuses an unmapped verb or a path naming nothing in the WIT, so growing the ABI without growing the world fails loudly. Deferred-effect semantics (snapshot reads, later-applied writes, read-after-write reads old) are part of the freeze, with batching (`pose`, one event struct) as the amortized hot path and the same fixed-step determinism. The per-language cross-build path (`GUEST_TOOLCHAINS`: Rust first, Python/TS as the GC-language gate, Go/C#/Kotlin/C after it) lives next to the existing Rust one.
- [x] Host sandboxed scripts beside `libloading`, with per-tick fuel/deadline like `portable.rs:40`. `blockloom-runtime/src/script_wasm.rs` runs core wasm modules (the shape web scripts already ship) under wasmi: only the three `blockloom.read_number/read_text/act` imports (anything else, including WASI, is refused at load), 64 MiB ceiling, 10 ms fuel on hot entries and 50 ms on rare ones, and a trap or an empty tank stops the script with an error effect rather than the run. WASI imports stay gated by having none; wall-clock, RNG and tasks remain host services, as with plugins. wasmi-first is deliberate: it reuses the web artifact and the in-tree interpreter, leaving the `wasmi` vs `wasmtime` component-model call (open question below) to be made on numbers rather than up front.
- [x] Gate: one non-Rust language driving `start/tick/event` in a test world with fuel limits, at measured overhead vs native. A hand-written WAT module - the imports, memory and entries being the contract, not the source language - says hello on `start`, reads its x and steps +1 on `tick`, and answers `event`, all asserting the same `Effect`s a native script produces; a spinning module is stopped with a budget error and stays stopped. Ignored `wasm_tick_cost` measures both: wasm ~2.9 us vs native ~0.55 us per read+act tick (5.3x, single-digit microseconds either way), so per-tick wasm scripts are affordable and the remaining risk is each GC language's own lift cost.
- [x] Editor wiring: Play builds the wasm beside the native library and the run prefers native with wasm as the fallback. `build_scripts_for` compiles each script for `script::WEB_TARGET` too when this machine has that target's std (best effort: a wasm-only failure never fails Play, and cross-target builds are untouched). `ScriptBackend` (`engine.rs`) loads native first and falls back to the sandbox when the library is missing or won't load, or wasm first under `BLOCKLOOM_SCRIPT_BACKEND=wasm`; `is_built` counts either artifact so a wasm-only project plays. All lifecycle entries dispatch through the enum, so fixed/frame/UI/stop/destroy/event behave the same on both.
- [x] First guest crate in Rust, against the frozen world. `blockloom-script-guest` binds `blockloom:script@0.1.0` (`wit/world.wit`, byte-identical to `wit::WIT` by test) as a core wasm module over the same three imports: typed homes for the hot paths (`lifecycle`, `state`, `vars`, `lists`, `physics`, `plugins`), the `Event` struct beside the numeric `on-event`, generic `sensors`/`texts`/`acts` escapes, and every numeric verb as a constant pinned verb for verb against `abi.rs` by a drift test. Hand-lowered rather than macro-generated, because the host is core wasmi: the same WIT file feeds real `wit-bindgen` when the component call is made. `templates/minimal.rs` drives `start`/`tick`/`event` through the binding only, and a runtime test builds it with two `rustc` runs (the documented `cargo build --target wasm32-unknown-unknown` without the cargo) and holds its effects against the hand-written fixture's. Next slice: the Python/TS GC-language gate (blocked, see the C item below).
- [x] Script calls for save slots and interface language (ABI 47), closing the gap the slots/i18n feature left: `switch_save_slot`/`delete_save_slot`/`set_language` produce the same effects the blocks do, and `save_slot`/`save_slots`/`language`/`text_for` read the same snapshot with the same fallbacks. The guest crate binds them as `saves`/`locale`, the WIT tables carry the new rows, and a compiled-script test holds reads and effects against the blocks'.
- [x] C as the second guest language (`blockloom-script-guest/c/blockloom.h`, `templates/minimal.c`). A freestanding header over the same three imports: the 56-byte `bl_call` record, `bl_read_number`/`bl_act` and thin helpers (`bl_say`, `bl_axis`, `bl_change_position`, `bl_set_data`, `bl_switch_save_slot`, `bl_set_language`), exports named with `export_name`, no libc and no WASI, built by one `clang --target=wasm32 -nostdlib -Wl,--no-entry -Wl,--export-memory`. `c_header_covers_every_abi_verb` holds every verb number and the ABI version to `abi.rs`; `c_guest_script_runs_in_sandbox` loads the built module and asserts the same effects as the Rust guest and the WAT fixture (skipped without clang). The ignored `wasm_tick_cost` prints the C guest's per-tick cost beside the fixture's.
- [x] Component host (desktop only), resolving the `wasmi` vs `wasmtime` question: both coexist. `blockloom-runtime/src/script_component.rs` runs a wasm component under wasmtime (cargo feature `components`, default on, built only off wasm32 and Android, so the web and Android players keep wasmi with Rust and C guests). The guest imports the typed `blockloom:script@0.2.0` interfaces and exports `entry`; every import lands on the same `number_for`/`text_for`/`act_for_asked` the native and wasmi paths use, so snapshot reads, deferred writes and read-after-write are unchanged. The sandbox is a 256 MiB memory ceiling, fuel per call (10 ms hot, 50 ms rare) and an empty WASI context (guest runtimes import WASI for their own startup; they get no files, sockets, environment or arguments). A script path ending `.wasm` is prebuilt by its language's toolchain: Play skips rustc for it, `ScriptBackend` loads a component under wasmtime and a core module under wasmi. The decision came through the project coordinator, not a verified user message.
- [x] World 0.2.0. The 0.1.0 text did not parse (`lifecycle` defined `pose` as both a record and a function) and declared no export a guest could implement. 0.2.0 renames the record `pose-data`, moves `start`/`tick`/`frame`/`ui`/`stop`/`destroy`/`on-event` into an exported `entry` interface, and a `wit-parser` test now resolves the text, so it cannot rot again. Nothing had shipped against 0.1.0.
- [ ] Python/TypeScript GC-language gate: Python builds with componentize-py (`templates/minimal.py`) and runs under the host; the ignored `a_python_component_runs_and_costs_what_it_costs` prints load and per-tick cost for a given component. Measured (debug host build, 18 MB CPython component): 16 us per read+act tick (about 5x wasmi's core module and 30x native, still far inside a 16 ms frame), but a 5 s first load, all of it Cranelift compiling the interpreter. Caching the compiled artifact (`Engine::precompile_component`) is the open follow-up. TypeScript (componentize-js) is next, then Go (TinyGo), C# and Kotlin.

## Open questions

- Ship a toolchain or remove the dependency: bundle `rustc`, offer an optional interpreted scripting tier for edit-time iteration, or keep requiring the user's toolchain and improve the missing-toolchain guidance. Multi-language WASM multiplies this: one toolchain per guest language (TinyGo, .NET WASI, Kotlin/Wasm, wasi-sdk). Packaged installs cannot assume any of them (known gap).
- Hot reload scope: recompile + reload a single script in the scene view without a full rebuild, and define what happens to per-actor storage across reloads.
- Debugging story: headless test harness for scripts (VM-equivalence style, as in `tests/codegen.rs`) vs full debugger attach; pick one before promising breakpoints.
- Web/Android parity: keep the three-call ABI as the portable surface until the WIT world replaces it; any new verb needs the wasm import path and the Android packaging path at the same time. A script WIT world must ship guest bindings and host support on all three targets at once.
- `wasmi` vs `wasmtime`: decided (via the coordinator): both coexist. wasmtime hosts script components on desktop only; wasmi stays for the web and Android players, plugin modules and core-module scripts. Revisit if a component guest is wanted on the web.
